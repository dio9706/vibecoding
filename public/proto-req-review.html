接口契约

GET /api/food/recommend?ageMonth=6&page=1&size=20

// 200
{
  "list": [{ "id": 1024, "name": "南瓜米糊", "ageMonth": 6, "tags": ["高铁", "易消化"] }],
  "total": 37,
  "hasMore": true
}

ageMonth 仅接受 6 | 8 | 12 | 18，传其它值返回 400，前端需在切换时做白名单校验。

关键实现点

筛选必须走后端查询，不做前端本地过滤

旧版曾用前端本地筛选，数据量涨到 3 万条后卡死下线。本次一律传 ageMonth 由后端过滤，前端不缓存全量列表。

首屏默认月龄

进入页面时不预选任何档位，展示全部月龄推荐，首屏请求不带 ageMonth。

筛选态与 URL 同步

切换月龄用 router.replace 而非 push — 否则用户连点四档后要按四次返回键才能退出页面，这是 v1 评审时提过的问题。

切档时的分页处理

切换月龄时清空分页状态回到第一页。此项你标为不确定，按默认判断处理；已按你的补充说明在切档时加了 loading 占位，避免旧数据闪现。

空结果兜底

场景 展示 埋点
某档月龄无推荐 「该月龄暂无推荐，试试其它月龄」+ 快捷切换 food_empty_by_age
全部月龄均无推荐 通用空状态 + 返回首页 food_empty_all
请求失败 保留上次结果 + toast 提示 food_fetch_fail

风险与遗留

分页与筛选叠加时后端 total 按筛选后统计。前端若缓存旧 total 会导致「加载更多」提前停止，需在切档时清空分页状态。
  • 宝宝档案自动匹配月龄本期不做，留待下期
  • 四档月龄为硬编码，后端未提供枚举接口 — 后续增档需前后端同时改
